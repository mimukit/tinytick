# QA Plan: tinytick v1

_Generated 2026-10-07 · against `91676a2` (uncommitted changes: the whole v1 build on `feat/tinytick-v1`) · covers plan phases 0 to 6_

## Summary

- tinytick is a Tinycast extension that manages TickTick tasks through the TickTick web API, with no TickTick desktop app.
- It works when Quick Add, the Today screen keys, the checklist, and sync change the real TickTick account, and TickTick web shows the same data.

## Environment

True for the whole plan. Do this once, before Scenario 1.

- Use a Mac with Tinycast installed. Turn on extensions in Tinycast Settings › Extensions.
- Quit the TickTick desktop app. Keep it closed for the whole run.
- Use a real TickTick account on `ticktick.com`. The plan adds and deletes tasks only in one list, the *QA list*.
- Keep TickTick web open in a browser at `https://ticktick.com/webapp`. Reload it to compare after each change.
- Use the branch `feat/tinytick-v1`.

Clone and build the branch:

```sh
git clone -b feat/tinytick-v1 https://github.com/mimukit/tinytick && cd tinytick && pnpm install && pnpm build
```

- In Tinycast, open Settings › Extensions › Install New › Add from folder. Pick the `dist/` folder.
- Get an API token: in TickTick web, open Settings › Account › API Token, and create one. Keep it in your clipboard manager or a note.

- [ ] Environment ready

### TC-1.1: Sign-in prompt and token login  ·  🔴 Critical

**Goal.** A new user sees a sign-in prompt, a bad token fails cleanly, and a good token signs in and syncs.

**Steps**

1. Open Tinycast and run **Today**.
   - [ ] The screen shows "Sign in to TickTick" with an "Open Account" action
2. Press Enter on "Open Account". Select "Sign in with an API token" and press Enter.
3. Type `not-a-real-token` and submit.
   - [ ] A failure toast says TickTick rejected the token, and the form stays open
4. Paste the real API token and submit.
   - [ ] A toast says "Synced N lists, M tasks", and the numbers look right for your account
   - [ ] The Account screen shows "Signed in with an API token" and a last-sync time of now
5. Quit Tinycast fully, open it again, and run **Account**.
   - [ ] The Account screen still shows "Signed in with an API token"

### TC-1.2: No secret in the plaintext data file  ·  🔴 Critical

**Goal.** The API token is in the Keychain and not in Tinycast's plaintext extension data file.

**Steps**

1. Copy the first 8 characters of your API token. Run this command, with those characters in place of `TOKENSTART`:

   ```sh
   grep -c "TOKENSTART" ~/Library/Application\ Support/com.tinycast.app/extension-data/*tinytick*.json
   ```

   - [ ] The command prints `0`
2. Open the Keychain Access app and search for `com.tinycast.extensions.oauth`.
   - [ ] One item exists for tinytick

- [ ] Pass

### TC-1.3: Browser sign-in with your own TickTick app  ·  🟡 Normal

**Goal.** Find which redirect URI, if any, lets browser sign-in finish in Tinycast. The plan treats this as an open question.

**Steps**

1. In a browser, open `https://developer.ticktick.com/manage` and create an app. Add all three redirect URIs:
   - `https://raycast.com/redirect?packageName=Extension`
   - `tinycast://oauth`
   - `raycast://oauth?package_name=Extension`
2. In Tinycast, open the tinytick extension preferences. Paste the client ID in "OAuth client ID".
3. Run **Account**, open "Sign in with the browser", enter the client secret, and pick the first redirect URI. Submit and approve in the browser.
   - [ ] The browser returns to Tinycast, and Account shows "Signed in with the browser"
4. If step 3 fails, sign in with the token again, then repeat step 3 with `tinycast://oauth`, and then with `raycast://oauth?package_name=Extension`.
   - [ ] Record in Notes which redirect URI works, or that none works, with the error text

**Result**

- [ ] Pass
- [ ] Fail
- [ ] Skipped
